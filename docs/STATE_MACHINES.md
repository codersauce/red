# Red runtime state machines

Audited against Red 0.11.1, commit `5b15a726`. States below describe what the next event may do. Several machines run at once. For example, a clean buffer can own a pending write, and a running agent turn can own a write that is waiting for a decision.

## Confirmed issues, in impact order

P1 covers lost or unauthorized file writes and competing owners of recoverable work. P2 covers interrupted workflows, incorrect history and protocol errors. Issue numbers stay stable as priority changes. The examples use real editor handlers, files in temporary directories, bounded channels, and formatter responses. The reproductions below failed with the original handlers. The regression table records what each retry or recovery check observes.

| Issue | Impact | Reproduced transition and observed result | Status |
|---|---|---|---|
| 1. Competing file saves | P1. Several editors could report success and clear their dirty flags for different bytes at the same path. | Release four writers from a barrier after each has prepared different contents against the same baseline. All four reported success creating the same file. The regression also exercises an existing file. | Fixed |
| 2. Agent write ownership | P1. Unsaved human text reached disk without a current approval. | Approve Save All, reopen the same path, type a private prefix, then accept a new tool request into the editor. The old choice matched the new buffer's save counter and silently wrote the prefix. If a write timed out while queued or at the confirmation dialog, Red still applied it. | Fixed |
| 5. Detached and recovery session ownership | P1. A second owner could remove the first owner's socket and credentials during startup. Two interactive editors could also rotate the same recovery store. | Bind a real Unix socket and expose the same state observable before PID publication. A second bind to that name succeeded. A second snapshot writer also entered a rotation while the first writer held its directory open. | Fixed |
| 3. Save and quit while formatting | P2. A late response redirected subsequent editing, or a requested write never happened. | Start Save As from an unnamed buffer, force-save to a second path, then deliver the first formatter response. Red restored the unnamed identity. Run `:wq` on clean, unformatted text with a pending formatter and the editor returned quit before the formatter could write. | Fixed |
| 4. Turn interruption and history | P2. Red could suppress its output and tools, mistake an old interrupt failure for the current turn's, or record the wrong result. | Reject an interrupt while a follow-up is queued. The worker kept its cancelled flag and the editor kept Stopping. Complete turn A, start and interrupt B, then reject A's interrupt. B lost its pending interrupt. A turn the provider reported as interrupted was recorded as Completed in inline history. | Fixed |
| 6. Husk LSP request lifetime | P2. Late cancellation poisoned a future request with a reused ID. The server continued accepting requests after shutdown. | Complete request 2, receive a delayed cancellation for 2, then issue a different request with ID 2. It returned RequestCancelled. Before initialization the server returned InternalError for a feature request. | Fixed |

## Editor, storage, and recovery

An **explicit** machine has a named phase or mode in source. An **implicit** machine derives its phase from the presence of an owner, a pending entry, a revision, a resource, or a combination of these. The tables describe application behavior at event boundaries. Rows sharing a machine name are alternative transitions. The named handlers and types are search anchors for the implementation.

| Machine and representation | From | Event or guard | To and invariant |
|---|---|---|---|
| Modal input, explicit `Mode` | Normal | Insert, visual selection, colon or search key | Insert, Visual, VisualLine, VisualBlock, Command or Search. Dispatch follows the active mode. |
| Modal input | Insert or visual family | Escape, complete change, or change selection kind | Normal, or another visual mode. An insert group commits at its editing boundary. Command and Search submission or cancellation close the prompt. |
| Normal-mode composition, implicit `PendingOperator`, count, mark, register, macro and character-motion fields | Idle or prefix pending | Count, operator, register, mark, macro or find prefix, then another key | Accumulate the count or wait for its operand. A valid operand consumes the prefix. Cancellation ends the pending sequence. Recording, playback and dot-repeat retain different command data. |
| Multi-cursor, explicit `MultiCursorPhase` inside an optional session | Absent → Selecting | Add occurrences or cursors, then insert/replace | Inserting. Selections belong to one stable buffer and window at a tracked revision. End/reset drops the session, and an owner change invalidates it. |
| Mouse selection, implicit gesture | No gesture → pressed | Drag, timer autoscroll, release, or owner/revision change | Start or extend the correct visual selection, finish it on release, or abandon a stale gesture. Double/triple clicks select another unit. |
| Snippet placeholders, implicit optional `SnippetSession` | No snippet → installed tab stops | Navigate, replace a stop, edit across it, or leave | Keep transformed anchors in the owning buffer, move to the next/previous stop, then end at the final cursor or invalidate the session. |
| Undo tree and save marker, implicit | At root/node, no open transaction | Begin and record replacements, commit | Empty group drops. A nonempty group creates a child with a fresh revision. Undo selects the parent, redo its selected child. Editing after undo preserves siblings until pruning. |
| Edit publication, implicit `EditBatch` | Idle → collecting | Local replay edits, barrier action, yield/cancel, leave outer batch | Text changes synchronously. Changed buffer IDs accumulate once. Flush before an external observer or at the boundary. Nested/suspended batches retain the enclosing ownership. |
| File buffer, implicit rope baseline plus `ExternalFileChange` | Loaded or missing → edited | Save, Save As, force write, external create/change/delete | A successful write alone publishes its new backing identity and saved bytes. Failed writes preserve local edits. A clean externally modified buffer can reload. A dirty buffer or deleted file is flagged for resolution. |
| Concurrent file publication, implicit filesystem state (issue 1) | Missing destination | Normal save against absence | Write complete contents to a sibling temporary file and publish without replacement. A competing creation fails. |
| Concurrent file publication | Previously loaded destination | Normal save against known bytes | Open without truncation, acquire the file lock, compare the saved bytes on that handle, then write and resize. Aliases of an existing inode keep their identity. Force permits deliberate replacement of contents. The advisory lock coordinates cooperating writers. An external program ignoring it can still modify an existing file concurrently. |
| Formatting and quit, implicit request maps plus explicit `DeferredQuit` (issue 3) | Idle | Request format during a normal save | Pending, keyed by request and stable buffer ID, URI and text revision. Save As temporarily routes LSP to the destination. Repeating a pending formatted save coalesces. |
| Formatting and quit | Pending | Valid reply, stale edit, malformed edits, unavailable formatter, or a later direct save | Apply and write, cancel and restore a still-owned provisional name, retry eligible edits once, or save unformatted on the supported fallback. A successful direct write retires the older request for that buffer. |
| Formatting and quit | None → AfterSaves | Quit with outstanding saves and every dirty buffer covered | Wait for all requested saves, including clean inputs. Failure or a missing save cancels. Success of the last write sets Ready. Consuming Ready rechecks all buffers for intervening changes. Standalone forced quit bypasses this wait. In a write-and-quit command the write must succeed or have its own matching pending request before quit proceeds. |
| Buffer/window/panel ownership, implicit focus and split tree | Active editor window, panel, or workspace | Split, switch, zoom, close or restore | Active view is rebound to a surviving window/buffer or to the panel/workspace owner. Window-local cursor and viewport follow that view. Stable window and buffer IDs distinguish an object from its current vector index. |
| External file watch, implicit mailbox and fingerprints | Untracked → tracked | Native event or fallback poll | Compare exact backing bytes before reload/conflict. Directory-watch updates share a worker and coalesce current paths. Closing a buffer drops its watch entry. |
| Recovery writer, implicit writer handle and persisted generation | Disabled, due, unchanged or backing off | Tick, change, shutdown, writer completion | At most one background writer per editor. Interactive resume claims the selected namespace and re-reads the snapshot under that claim. A second live writer is refused. A successful generation can suppress duplicate writes. A failure stays eligible after backoff. Shutdown drains the writer. |
| Recovery store, implicit disk generations | No snapshot, valid latest, or only valid previous | Write a bounded snapshot, sync temporary file, rotate and publish | Load validates the newest snapshot and falls back to previous on missing/invalid data. Only a valid latest may replace previous. A fault after rotation leaves previous recoverable on retry. Schema migration and undo-tree validation precede restoration. |
| Agent conversation persistence, explicit claim and implicit save throttle | Unclaimed | Claim the normalized workspace | Owned may save/retire. HeldElsewhere or refused stays excluded for that editor. Dirty revisions are throttled, failed removal is retried, and release/drop relinquishes owned locks. |

## Agent, inline assistance, and language servers

| Machine and representation | From | Event or guard | To and invariant |
|---|---|---|---|
| Agent pane, explicit `AgentPanePhase` | Idle or saved/resumable | Submit, start, prepare or restore | Starting creates a thread. Restoring waits for the selected thread. A prompt waits in FIFO order until a session is available. Failed start holds it for retry. |
| Agent pane | Working | Submit, stop, finish or lose connection | Submit queues a bounded follow-up. Stop enters Stopping. A matching successful completion advances the queue unless paused. An unexpected interruption retains the prompt for Retry, Continue or Dismiss. Session loss distinguishes an unsent prompt from one whose edits might already have run. |
| Agent pane | Stopping or Restoring | Interrupt rejection, terminal event, restore success/failure, reset | Rejection returns to Working. A requested stop holds follow-ups at terminal. A failed thread switch keeps the prior conversation. Reset forgets the old thread and clears the queue. |
| Codex transport, implicit pending map | Disconnected → initialized | Start/resume/continue, configuration and requirements responses | Start/restore a local session only after its request succeeds. Models, history pages, inline requests and commit generation carry distinct request purposes. Errors complete the corresponding requester. Bridge exit drains outstanding requests and reconciles pane state. |
| Session search, explicit `ListPhase` | Titles | Page, cursor exhaustion, query with content search, oversized page | Continue Titles or enter Contents, then deliver one result. Seen IDs and cursors prevent duplicates/loops. Oversized pages retry with a smaller limit. |
| Provider turn and editor turn, implicit provider ID plus explicit Running/Stopping (issue 4) | Idle → start requested | Turn/start returns ID, stop before/after response | Retain ownership across startup. A stop before the ID is known is sent when it arrives. Only one interrupt is outstanding for that turn. The local optimistic turn ID and the provider turn ID have different owners. |
| Provider/editor turn | Stopping | Provider rejects the matching interrupt, or terminal event arrives first | Rejection resumes the same turn and allows a fresh interrupt. Terminal clears turn ownership and may release a waiting prompt. A delayed response for A has no authority over B. |
| Dynamic editor tool, implicit task/queue/oneshot (issue 2) | Admitted on a live provider turn | Wait for host, queue on editor, dwell in Follow, or wait for a dirty-buffer decision | Recheck admission after the host mutex and at editor dispatch. A revoked turn or expired response invalidates pending work. An already-applied edit remains applied if cancellation races delivery of its reply. |
| Dirty-buffer decision, implicit held tool and answer cache | Waiting for typing pause → shown | Keep unsaved, Save All, decline, timeout, close or cancel | A live answer applies to the held buffer. A reusable answer must match session, path, buffer incarnation and save generation. Expiry discards the question without authorizing a retry. |
| Inline job, explicit `InlineTurnState` | Draft → Pending | Provider result, cancel, failure, park popup | Parking preserves the request. A matching result may become Ready for review or Completed after apply. Failure or cancel ends the request. A duplicate result cannot apply a terminal turn again. |
| Inline review, explicit popup and history states | Ready, including a wider proposal | Accept, decline, recheck or fail target validation | Applied/Completed, Declined or Rejected. Wider scope requires review. History distinguishes source Unchanged, Changed and Detached. Kept, Undone and Superseded describe disposition independently of provider completion. |
| Inline handoff receipt, explicit `InlineAgentState` (issue 4) | Running | Actual writes, local stop acknowledgment, provider terminal or lost bridge | Keep recording writes for the owning turn. An acknowledgment alone leaves it running. Provider success, failure and interruption produce Completed, Failed and Cancelled respectively. History retains the actual edits. |
| LSP process and routing, implicit client flags, queue, instance and route | No client → starting | First matching document/request starts server, then initialize succeeds/fails | Ready dispatches supported requests to a selected server. Queued requests carry size, deadline and identity. Failure/timeout retires them. Closing a document retires its queued requests across aliases. |
| LSP document synchronization, implicit per-URI opens and per-buffer edits | Closed → opened | Canonical edits, revision gap, didSave or didClose | Coalesce contiguous edits. Incremental delivery requires a matching before-image and supported line encoding. Full-text fallback rebuilds from the current rope. Open membership and revisions are separate from diagnostics. |
| LSP query and edit, implicit request snapshots | Requested → pending | Response, cancellation, timeout, server replacement or edit | Requests carry the relevant buffer, URI, revision, cursor or server identity. Validate before applying edits. Multi-document plans prepare affected files first. Agent rename previews have a session-owned plan ID and expire. |
| Completion, signature and snippets, implicit pending and displayed snapshots | Hidden → scheduled/pending | Fresh response vs superseded request, cursor/mode change or dismissal | Show only the current completion/signature. Resolution belongs to the selected item. Accepting a snippet installs its placeholder session. Signature help can update while the editor retains input focus. |
| Copilot, explicit sign-in phases and implicit completion worker | Off/idle → sign-in or desired completion | User confirms, provider issues device code, finish sign-in or retry | Dialog moves among Ready, Waiting, Requesting and Failed. A fresh provider completion can become a preview. Accept/dismiss consumes it. A changed buffer, cursor or selected completion invalidates stale previews. |

| Shell/filter job, implicit process and optional filter target | Submitted → running | Output chunks, cancel, exit/failure | Bound output and finalize the job. | Git dashboard refresh, implicit process/timer IDs and pending flags | Idle → scan active | Timer or explicit refresh during scan, outputs, exit or spawn failure | Coalesce work while busy. | Project search and file picker, implicit request generations and scan leases | No query → scanning/ranking | Change query, receive batch, close or reopen | Only current-generation results update the picker. | Markdown images, explicit remote slots and implicit render placements | Unseen → Loading | Decode/fetch completes, fails, viewport changes | Ready reuses decoded pixels. Failed retains an error. Placement lifetime follows visible geometry. A local image slot also checks file metadata. |
| Update worker, implicit pending oneshot and cross-process locks | Off, scheduled or idle | Startup deadline or explicit update | At most one pending worker per editor. A locked timestamp coordinates daily checks. Managed install verifies receipt, signature, checksums and staged binary, then replaces it. Shared detached-session/exclusive installer locks can defer replacement. |
